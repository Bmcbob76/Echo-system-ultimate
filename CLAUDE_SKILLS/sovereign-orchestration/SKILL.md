### MCP Tools

**masterorch_health**
- Check orchestrator health status
- Returns: service status, routing active

**masterorch_route**
- Route prompt to best model based on task analysis
- Parameters: prompt (string), strategy (string, default: "auto")
- Strategies: auto, fastest, highest_quality, cost_effective, specialized

**masterorch_multi_query**
- Query multiple models in parallel
- Parameters: prompt (string), models (array, default: [])
- Returns: aggregated responses from all models

**masterorch_consensus**
- Get consensus from multiple models on critical tasks
- Parameters: task (string), models (array, default: [])
- Returns: agreement level, consensus result
- Requirement: 95% agreement for consensus

### Routing Strategies

**1. Auto Routing**
- Analyze task complexity and requirements
- Select optimal model automatically
- Balance speed, quality, and cost

**2. Fastest Response**
- Route to models with lowest latency
- Prioritize speed over quality
- Use for real-time interactions

**3. Highest Quality**
- Route to most capable models
- Prioritize accuracy and depth
- Use for critical analysis

**4. Cost Effective**
- Route to most economical models
- Balance quality with token costs
- Use for bulk operations

**5. Specialized Routing**
- Route to domain-specific models
- Match task type to model strength
- Use for technical or creative tasks

### Consensus System

**Process:**
1. Submit task to 3+ models in parallel
2. Collect all responses
3. Analyze similarity and agreement
4. Calculate consensus score
5. Return agreed-upon result or escalate

**Requirements:**
- Minimum 95% agreement for consensus
- At least 3 models for valid consensus
- Automated expert escalation if no consensus
